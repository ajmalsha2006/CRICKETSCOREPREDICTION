# Cricket First-Innings Score Prediction

A local machine learning project that estimates a cricket team's final first-innings score from the match situation so far. It includes a Jupyter training workflow, data preparation with big data tools, MLflow experiment tracking, and a Streamlit interface for predictions and run comparisons.

## What it does

- Uses match and ball-by-ball cricket data to build innings and over-level examples.
- Trains a Random Forest regressor to estimate the final first-innings total.
- Trains a separate Logistic Regression classifier to predict whether the innings reaches 180 runs once at least 16 overs are complete.
- Provides a Streamlit form for entering the batting and bowling teams, season, venue, city, current score, wickets, overs and deliveries faced.
- Shows score estimates, estimated runs remaining, current run rate, and (when eligible) the late-innings 180+ probability.
- Tracks training runs, parameters, metrics and artifacts with MLflow. The Streamlit app includes an MLflow run comparison page.

## Big data tools

| Tool | Use in this project |
| --- | --- |
| DuckDB | SQL queries over CSV and Parquet data, plus data quality checks. |
| Parquet | Compressed columnar storage for processed match and delivery tables. |
| Dask | Aggregation of delivery records by match and over. |
| Polars | Creation of cumulative innings progression features. |
| MLflow | Tracking model training runs, parameters, evaluation metrics and artifacts. |

These are used as local Python tools. The project does not require HDFS, WSL or Docker for the current workflow.

## Requirements

- Windows 10 or 11, 64-bit
- 64-bit Python 3.12 recommended for dependency compatibility
- VS Code with the Python and Jupyter extensions
- Git

The Python libraries are listed in `datasets/requirements.txt`. Jupyter is needed to execute the training notebook and may be installed separately.

## Setup on Windows

Open a PowerShell terminal in the project folder (the folder containing `app.py`) and create an environment with Python 3.12:

```powershell
py -3.12 -m venv .venv
```

If the Python Launcher (`py`) is unavailable, create the environment with the full path to the installed Python 3.12 executable:

```powershell
& "$env:LocalAppData\Programs\Python\Python312\python.exe" -m venv .venv
```

Install the project requirements and Jupyter using that environment's Python:

```powershell
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r datasets\requirements.txt
.\.venv\Scripts\python.exe -m pip install jupyter
```

Use this same `.venv` environment for the notebook and app. In VS Code, select `.venv` as the Python interpreter and notebook kernel.

## Train the models

Run this from the project folder:

```powershell
.\.venv\Scripts\python.exe -m jupyter nbconvert --to notebook --execute --inplace first_innings_score_prediction.ipynb
```

The notebook reads `datasets/matches.csv` and `datasets/deliveries.csv`, performs quality checks, prepares Parquet data and model features, trains and evaluates the models, saves outputs under `models/`, and logs a run to the local MLflow tracking store.

You can also open the notebook in VS Code, choose the `.venv` kernel, and select **Run All**.

## Run the app

After the notebook has completed successfully, start Streamlit from the project folder:

```powershell
.\.venv\Scripts\python.exe -m streamlit run app.py
```

Streamlit prints a local address in the terminal and usually opens the app in a browser. Use the **Score Predictor** tab for predictions and **MLflow Run Comparison** to review training runs.

## Troubleshooting

### `No module named streamlit`, `joblib`, `sklearn` or `mlflow`

Install requirements into the same environment used to start the app:

```powershell
.\.venv\Scripts\python.exe -m pip install -r datasets\requirements.txt
```

Then always launch the app with:

```powershell
.\.venv\Scripts\python.exe -m streamlit run app.py
```

### PyArrow fails to build

Use 64-bit Python 3.12 and create a fresh virtual environment with that interpreter. Python 3.15 may cause pip to try building dependencies from source on Windows.

### The app says the trained model is missing

Check that both source CSV files are present, then run the training notebook successfully. The notebook generates the model and supporting evaluation files used by the app.

### MLflow shows no training runs

Run the notebook with the same project copy and Python environment. The app reads the local `mlflow.db` and `mlartifacts` in the project folder, so those files are specific to that clone unless shared or regenerated.
